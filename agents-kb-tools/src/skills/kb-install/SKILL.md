# התקנת כלי הידע

אתר את רכיב הכלים לפי הנתיב הפיזי של הסקיל. קרא את הוראות המופע ואת
[חוזה הכללים](../../method/rule-contract.md) לפני יצירת פרופיל. הקוד, החוזה והסקילים
נמצאים ב־src; docs מתעד את פרויקט הכלים.

1. השתמש ב־Python 3.11 ומעלה ו־PyYAML 6; להתקנה בחר סביבה מבודדת באמצעות uv.
   אין התקנה אוטומטית של תלויות או שינוי PATH כחלק מפעולת build.
2. הגדר פרופיל עם נתיבי מקורות יחסיים למופע, aliases, הקשר ותקציבי פלט.
   רוץ קודם עם validate, ואז build עם root ו־output מפורשים.
3. סקור AGENTS.md, auto-review.md ו־manifest.json. בדוק כל שינוי בתחולה וביעדים,
   את כל ההיתרים והחריגים ואת היעדרם של מקורות היסטוריים ומידע אישי בדוגמאות.
4. לפני חיבור חי הצג את התוצרים וקבל את האישור שדורש המופע.
   עבור Codex חבר את AGENTS.md בערוץ ההנחיות שנבחר ואת תוכן auto-review.md
   כמחרוזת auto_review.extra_policy, לצד המדיניות הקיימת. בדוק managed policy
   שעלולה לגבור על ההגדרה המקומית. אל תחליף את policy או את הוראות הבסיס.
5. ב־Claude חבר את תיקיית claude/rules שנוצרה לטעינה הטבעית; ב־Cursor השתמש
   בקובץ mdc שנוצר. ודא שאין במקביל טעינה של הגופים המלאים או עותק hook נוסף.
   תוצר מלא שייך להקשר אחד: לחיבור גלובלי בחר פרופיל מכונה בלבד.
   כשכבר נטענת ליבת מכונה גלובלית, לפרויקט חבר רק את קובצי project שנוצרו,
   המכילים את ההפרש. במדיניות המבקר השתמש בתוצר המלא של ההקשר המתאים,
   משום ששדה extra_policy הוא מחרוזת אחת; אל תאבד את כללי המכונה בהחלפה.
6. בצע בדיקת טעינה בסשן חדש ומבחן זנב שניתן לצפייה. אל תסיק הצלחה מתשובת הסוכן בלבד.
   פלט hook מוגבל בנפרד עם --hook; חריגה נכשלת ואינה נחתכת. כשכל התוצר אינו נכנס,
   השתמש בטעינה טבעית וב־hooks לתזכורות ממוקדות בלבד.

אין להסיק מחיבור המדיניות שכל כתיבה נבדקת: רק בקשות אישור שמגיעות למבקר
נבדקות. בחירת פעולות המחייבות אישור היא החלטה נפרדת. שמור את המצב הקודם
לחזרה, אמת את מקור הסקריפטים המקושרים, ואל תצביע על worktree זמני שיימחק.

תיעוד רשמי: [Codex Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review).
