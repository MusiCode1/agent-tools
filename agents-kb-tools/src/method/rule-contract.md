# חוזה כלל ותמציות — גרסה 1

כל כלל הוא Markdown עם גוף מלא ו־frontmatter: id יציב באותיות לטיניות/ספרות/מקפים (שומרים מזהים קיימים),
title, audience: [agents], scope כרשימת machine:/project:/service:,
injection עם session ו־auto_review כבוליאנים מפורשים, summary ו־read_when לא ריקים.
review_summary אופציונלי ומשמש את המבקר במקום summary בלבד. אין יצירת תמצית אוטומטית מתוך גוף הכלל.

scope בהתאמת OR. inject: always עוקף את סינון ההיקף; inject: false חוסם שני יעדים
ואסור שיהיו לצידו דגלים פעילים. scope ריק ללא always אינו מתאים לשום הקשר.
שמות תיקיות אינם מעניקים תחולה. aliases חלים רק על מכונות. שירות נבחר מפורשות
באמצעות --service; הופעת שירות בדף ויקי אינה מפעילה את כלליו.

פרופיל JSON דורש version: 1 ו־sources כרשימת נתיבים יחסיים למופע. אפשר להגדיר
machine_aliases, context.machine ו־budgets לכל יעד עם chars ו/או bytes.
נתיב מחוץ למופע נדחה. סימלינקים לתיקיות אינם נסרקים וקישורי קבצים אינם מקור נוסף.
חומר history/archive/היסטוריה או מטא־דאטה היסטורי מוחרג גם אם סומן always.
שדה חובה חסר, id כפול, יעד לא תקין או חריגה מתקציב מכשילים את היצירה.

דוגמה סינתטית:

```yaml
---
id: confirm-release
title: אישור פרסום
audience: [agents]
scope: [project:demo]
injection: {session: true, auto_review: true}
summary: פרסום דורש אישור משתמש המכסה את היעד והגרסה.
review_summary: לפני פרסום ודא שקיים אישור משתמש ליעד ולגרסה המבוקשים.
read_when: לפני פרסום
---
# אישור פרסום
הכלל המלא, היתרים, חריגים ודוגמאות.
```

תמצית מכילה את החובה עצמה, לרבות היתרים וחריגים הדרושים להכרעה. מקור ונתיב
נוספים אוטומטית. read_when הוא תנאי קריאה לסוכן, לא מנגנון שמפעיל כלי בעצמו.
למבקר מספקים תנאי הכרעה מספקים בתוך הטקסט; אין להסתפק בהפניה חיצונית.
הכרעתו אינה מחליפה אישור אדם שנדרש במפורש. כללים מותנים מציינים בתמצית את תנאי הפעולה.

build יוצר AGENTS.md, auto-review.md, תוצרים לטעינה טבעית ב־Claude וב־Cursor,
ומרשם מקורות עם hashes, תחולה, בחירה וגדלים. --check משווה ללא כתיבה.
כל התוכן נבדק לפני תחילת הכתיבה; כל קובץ מוחלף אטומית. אין עסקה אטומית בין הקבצים:
אל תחבר תיקיית build לצרכן חי לפני שפקודת build ו־--check הסתיימו בהצלחה.
הכלי אינו מתקין, אינו משנה קונפיג ואינו מפעיל מבקר. אין שחזור policy אוטומטי.

בהקשר עם project נוצרים גם קובצי project המכילים רק כללים שאינם נכללים
בפרופיל המכונה. כך אפשר לצרף אותם לליבה גלובלית בלי כפילות. תוצר מלא עם
כללי פרויקט אינו מיועד להתקנה גלובלית לכל הפרויקטים. מדיניות המבקר נשמרת
כתוצר מלא לכל הקשר; אין הנחה ששדות extra_policy ממקורות שונים מצטברים.
