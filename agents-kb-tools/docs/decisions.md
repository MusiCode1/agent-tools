# החלטות — השיטה

## 2026-09-08 — להשאיר `runbook`, לא לעבור ל-`playbook`

### הבעיה

עלתה הצעה להחליף את המונח `runbook` ב-`playbook` — בשם ה-`kind:`,
בשם התיקייה `workflows/runbooks/`, ובטקסט.

### מה המונחים באמת אומרים

**`runbook`** מגיע מ-operations קלאסי — הספר שהאופרטור *הריץ* לפיו.
מתאר **משימה אחת ידועה**, **ליניארי ודטרמיניסטי**: אותם צעדים, אותה תוצאה.
"איך מחדשים את התעודה", "איך מעלים את השירות אחרי שהדיסק התמלא".

**`playbook`** מגיע מפוטבול — ספר של **מהלכים רבים**, ובוחרים אחד לפי מצב
המשחק. משם לשני עולמות: תגובה-לאירועים/אבטחה ("כשמזהים כופרה, אלה
המהלכים" — מבוסס-החלטה), ו-Ansible (`playbook.yml`, קובץ הצהרתי של מצב
רצוי — היום כנראה האסוציאציה הנפוצה ביותר אצל מפתחים).

| | |
|---|---|
| **runbook** | משימה אחת · ליניארי · *"בצע את הצעדים"* |
| **playbook** | מצב עם ענפים · מבוסס-החלטה · *"אלה האפשרויות, בחר"* |

### הנימוק המכריע — ההבחנה כבר קיימת אצלנו

`rules/130-runbooks.md` כבר מגדיר שני סוגים:

```
| רנבוק        | workflows/runbooks/    | HOW — צעדים, פקודות, סדר |
| דיאגנוסטיקה  | workflows/diagnostics/ | עץ החלטה / בדיקות        |
```

וארבעת ה-`diagnostics` הם בדיוק מהצורה המסועפת — "להבחין בין כשל Access
לכשל origin", "חלונות תקוע אבל CPU נמוך — איך למדוד latency במקום ניצולת".

**במונחים מקובלים, ה-`diagnostics` שלנו הם playbooks, וה-`runbooks` שלנו
הם באמת runbooks.** החלפה הייתה יוצרת "playbooks" ליניאריים לצד
"diagnostics" מסועפים — כלומר המילה playbook הייתה מרמזת בדיוק ההפך ממה
שהיא מסמנת אצלנו. **מטשטש במקום להבהיר.**

### העלות שנמדדה

| מה | היקף |
|---|---|
| `kind: runbook` בפרונטמטר | 63 קבצים |
| הנתיב `workflows/runbooks/` | 47 קבצים |
| המילה `runbook` בכלל | 116 קבצים |
| **`rules/` — מוזרק בכל סשן** | **6 קבצים, עם נתיבים מלאים קשיחים** |

השורה האחרונה היא הקריטית: `110-homeassistant.md`, `120-bitwarden.md` ו-`100-gog.md`
מכילים נתיבי רנבוק מלאים. ונמדד שששת הרנבוקים המוזכרים בשמם ב-`rules` הם
**בדיוק אלה שנשלפים הכי הרבה** — נתיב שבור שם פוגע במה שעובד.

בנוסף: `130-runbooks.md` נקרא על שם המונח, ו-`global/policies/runbooks-automatic.md`
נושא אותו ב-`permalink`. והארכיון מחזיק 25,917 קבצי סשנים עם המילה — הם לא
ישתנו, כך שתקופת-ביניים שבה סוכן רואה שני מונחים בלי לדעת שהם זהים היא
עלות ודאית, במערכת שכל הבעיה שלה היא שליפה.

### מה נבחר

**להשאיר `runbook`.** השם מדויק ביחס לתוכן, ההבחנה מול `diagnostic` כבר
עובדת, והשינוי היה משלם 116 קבצים תמורת בלבול.

### חלופות שנשקלו

- **להחליף רק את `kind:` ולא את התיקייה** — זול (63 שורות + reindex של
  10.5 שניות), אבל משאיר `kind: playbook` בתוך `workflows/runbooks/`.
  חוסר-עקביות בלי רווח.
- **להחליף את שניהם + לשנות גם `diagnostic`** כדי לשמור על זוג עקבי —
  הצורה היחידה שהייתה קוהרנטית, והיקרה ביותר.
- **מונח עברי** — הכללים כבר משתמשים ב"רנבוק" ו"דיאגנוסטיקה" בגוף הטקסט,
  אז הפער היה בין שם התיקייה באנגלית למונח שנאמר בפועל. לא הצדיק שינוי.

### אם זה יעלה שוב

הדרך הזולה לנטרל בלבול בלי לשנות כלום היא שורת-שקילות ב-`130-runbooks.md`:
*"playbook = runbook. מסמכים ישנים וסשנים בארכיון משתמשים במונח הישן."*
