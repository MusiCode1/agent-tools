## 3. שורש הבעיה — מאומת בקוד המקור

`mimeconf`: `text/markdown = execm rclmd.py`.

`/usr/share/recoll/filters/rclmd.py` **כן** מפרסר את ה-frontmatter:

```python
def parse_md_file(self, text_content):
    """Extract YAML front matter and return it along with the body content."""
    frontmatter = yaml.safe_load(yaml_content)
    return frontmatter, body_content
```

ואז משתמש בו לשלושה דברים **בלבד** — `created`, `modified`, ו-`tags`:

```python
tags = self.extract_tags(frontmatter)
for tag in tags:
    output += b'<meta name="tags" content="' + ... + b'">\n'
```

ופולט את `body_content` — הטקסט **שאחרי** ה-frontmatter — כגוף המסמך.

**המילון נטען, שלושה מפתחות נשלפים, כל השאר נזרק. בלי שגיאה ובלי אזהרה.**

מכאן, מצב השדות באינדקס החי:

| שדה | מצב |
|---|---|
| `tags` | ✅ שורד כשדה המובנה `keywords` |
| `description`, `kind`, `domain`, `env`, `name`, `tool` | ❌ נזרקים |

**מדידה:** לכל רנבוק חולצה מילה שקיימת אך ורק בערך frontmatter (לא בגוף,
ולא שם-שדה), וחופשה:

```
האינדקס החי:     1/65
אינדקס בדיקה:   56/65
```

**זמין היום בחינם, בלי שום שינוי:** `keywords:byoca`, `keywords:badbox`,
`keywords:acp` — כולם מחזירים את הרנבוק הנכון מהאינדקס החי.

## 4. הפתרון — ארבעה רכיבים

### 4.1 `metadatacmds` — החזרת השדות הנזרקים

recoll מריץ פקודה חיצונית לכל קובץ וקולט את הפלט כשדות. בסעיף לפי-תיקייה,
כך שהיא רצה על 68 מסמכים ולא על 15,017:

```ini
[/home/user/Projects/agents-config/workflows]
metadatacmds = ; rclmulti1 = /home/user/Projects/agents-config/scripts/recoll-md-fields.sh %f
```

- **הנקודה-פסיק ההתחלתית חובה** — התיעוד: `Don't forget the initial semi-colon`.
- **`rclmulti1`** = "הפלט מכיל כמה שדות בפורמט `שם = ערך`". שם שדה רגיל
  היה קולט הכל כערך יחיד.

הסקריפט הוא awk טהור, בלי תלויות:

```bash
awk '/^---[[:space:]]*$/{n++; next} n==1' "$f" |
awk -F': *' '/^(description|tags|domain|kind|type|env|tool|name):/ {
    key=$1; sub(/^[^:]*: */,"",$0); gsub(/^["\[]|["\]]$/,"",$0)
    if (key=="description") key="rbdesc"
    if (key=="type") key="kind"
    printf "%s = %s\n", key, $0 }'
```

### 4.2 `~/.recoll/fields` — יכולת חיפוש והצגה

```ini
[prefixes]
rbdesc = XYDESC ; wdfinc=12
tags   = XYTAGS ; wdfinc=8
kind   = XYKIND
domain = XYDOM
env    = XYENV
tool   = XYTOOL

[stored]
rbdesc =
kind =
domain =
env =
tool =
```

- **`[prefixes]`** מפעיל את תחביר `kind:runbook`. תחילית `XY` לפי דרישת
  התיעוד לשדות מקומיים.
- **`wdfinc=12`** — מילה מ-`rbdesc` נספרת כאילו הופיעה 12 פעמים. משפט
  ה"מתי להשתמש" שוקל פי 12 מפסקה אקראית בגוף.
- **`[stored]`** — סעיף **נפרד** ונדרש כדי להציג. בלעדיו החיפוש עובד
  והתצוגה חוזרת ריקה.

> 🛑 **`description` ו-`summary` הם שמות תפוסים ב-recoll.** שדה מקומי בשם
> תפוס **נבלע בשקט** — מאונדקס, נשמר ריק, בלי שגיאה. עלה שתי ריצות
> בניסוי. לכן `rbdesc`.

**`NOT CURRENTLY IMPLEMENTED`**. `wdfinc` קיים אבל הוא פר-שדה, לא פר-תיקייה.
אין פרמטר "התיקייה הזאת חשובה יותר".

## 8. מה נשאר פתוח — לא בהיקף

- **`facts` ב-basic-memory** — 139 מסמכים באותה בעיה. הפורמט שונה
  (‏`permalink`, `type: note`), ולכן סקריפט חילוץ נפרד. אחרי שהמנגנון
  יוכיח את עצמו על `workflows/`.
- **חיתוך ההזרקה ב-40 פתקים** — ההוק קורא `recent_activity` עם
  `page_size: 40`, בעוד `project-a` מחזיק 59 פתקים ו-`agents-config` 43.
  **19 ו-3 פתקים בהתאמה בלתי-נראים בפתיחת סשן**, והחיתוך הוא לפי עדכניות
  — כלומר הידע הישן והיציב נופל ראשון. תיקון של שורה אחת ב-
  `hooks/session-start-memory.sh`, בלתי-תלוי במסמך הזה, וכדאי לעשות אותו
  בנפרד ומוקדם.
- **אכיפת אוצר-מילים** — C1 מזהיר בלבד. המעבר לכישלון-בנייה הוא החלטה
  נפרדת. התקדים שעובד: תקרת `global/facts` (19/25) + `check-memory-hygiene.py`.
- **שער עדכניות על `workflows/`** — 36 מסמכים לא נגעו בהם מאז הכתיבה,
  11 מעולם לא נשלפו. שדה `verified:` באינדקס. לא תלוי בשליפה.
- **ארגון מחדש לתיקיות נושא** — **נבדק ונדחה.** אם 12 התגיות הנפוצות היו
  תיקיות-על: 27 מ-69 המסמכים שייכים ל-2+ (עץ יאלץ בחירה שרירותית),
  21 לאף אחת (`misc/`), ורק 21 יש להם בית יחיד. הצירים ב-§4.2 נותנים את
  אותה יכולת חיתוך בלי המחיר.
