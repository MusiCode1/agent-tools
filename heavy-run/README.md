# heavy-run

עטיפה לפקודות כבדות שסוכנים מריצים במקביל על אותה מכונה: סוויטת טסטים מלאה, build, מדידה, בדיקת דפדפן.

היא עושה שלושה דברים:

1. **תור.** כל מכונה מקבלת מספר קבוע של מקומות (ברירת מחדל: מחצית מהליבות, לפחות 1). פקודה שלא קיבלה מקום ממתינה, ומדפיסה מה רץ עכשיו ומי הריץ: `waiting in queue (40s) — running now: [vitest · pid 1234 · /path · since 10:02:11]`. המקום משתחרר לבד כשהתהליך מת (`flock`).
2. **תקרת זיכרון.** הפקודה רצה ב-`systemd-run --user --scope` עם `MemoryMax` ו-`MemorySwapMax`. פקודה שחורגת נהרגת לבדה, עם קוד 137 והודעה שמזכירה את התקרה, והסוכנים והשרתים ממשיכים לרוץ.
3. **סביבה נקייה.** מסירה את `DC_DEPLOYMENT`, ‏`DC_DEPLOYMENT_DIR`, ‏`PORT`, ‏`FE_STATIC_DIR` ו-`NODE_ENV`. סוכן שרץ תחת שרת drive-coding יורש אותם, ושרת preview שעולה איתם מתנהג כמו השרת הראשי ומשתלט על הסוכנים שלו.

## שימוש

```bash
heavy-run -- bun run test                       # בתור, עם תקרה, סביבה נקייה
heavy-run --label fe-suite -- bunx vitest run   # שם שיופיע בתור
heavy-run --remote -- bun test                  # דרוש יעד SSH מוגדר
heavy-run --local -- bun run test:browser       # דפדפן ושרתים מקומיים
heavy-run --preview --label fso2 -- env DC_DEPLOYMENT=fso2 PORT=4397 bun src/bin/drive-coding.ts
heavy-run status                                # התור המקומי והתור ב-runner המוגדר
```

- `--preview` רץ תמיד מקומית, מדלג על התור ושומר על תקרת הזיכרון ועל ניקוי הסביבה. את משתני הפריסה שלו מגדירים במפורש אחרי `env`, כמו בדוגמה.
- `--no-queue` מדלג על התור במכונת ההרצה. `--keep-env` משאיר את משתני הפריסה של אותה מכונה.
- `--local` בוחר את המכונה המקומית. `heavy-run status --local` מציג את התור המקומי.
- `--mem-max SIZE` (ברירת מחדל `2G`), ‏`--swap-max SIZE` (ברירת מחדל `512M`).
- `--mem-high SIZE` — תקרה רכה שמאטה במקום להרוג. כבויה בברירת מחדל: תקרה רכה נמוכה עלולה להקפיא פקודה לדקות ארוכות במקום להפיל אותה.

משתני סביבה: `HEAVY_RUN_SLOTS`, ‏`HEAVY_RUN_MEM_MAX`, ‏`HEAVY_RUN_SWAP_MAX`, ‏`HEAVY_RUN_MEM_HIGH`, ‏`HEAVY_RUN_DIR` (ברירת מחדל `$XDG_RUNTIME_DIR/heavy-run`).

קוד היציאה הוא של הפקודה; 124 אם ההמתנה בתור נקטעה.

## מה נחשב כבד

סוויטה מלאה (`vitest run` בלי סינון, `bun test` על חבילה), build של production, מדידות ביצועים, בדיקות דפדפן. טסט ממוקד בקובץ אחד לא צריך תור.

## התקנה

מתוך תיקיית `heavy-run` צרו קישור ל־CLI. להשארת מצב מרוחק זמין שמרו את `remote.py` לצד הקובץ שאליו הקישור מצביע.

```bash
ln -sf "$PWD/heavy-run" ~/.local/bin/heavy-run
```

## Runner מרוחק

הגדירו SSH alias לחשבון ייעודי ב־runner עם מפתח ייעודי ו־host key מאומת. השאירו את ה־alias ללא `SendEnv` או `SetEnv`. התקינו את `heavy-run` ואת `remote.py` באותה תיקייה גם ביעד. ב־`PATH` של מעטפת SSH לא אינטראקטיבית צריכים להיות `heavy-run`, ‏Git, ‏Python 3.11 ומעלה, ‏`flock` ו־Bun לפרויקטים עם lockfile של Bun. הגדירו את מספר המקומות בתור ואת תקרות הזיכרון בסביבת החשבון או ב־wrapper שמפעיל את `heavy-run`. מנהל systemd של המשתמש נדרש להפעלת תקרות הזיכרון.

```bash
ssh -T -o BatchMode=yes build-runner heavy-run --runner probe
# heavy-run/1
```

### הפעלה לריפו מאושר

מתוך ריפו שמותר להעביר ל־runner, הגדירו את היעד בתצורת Git המקומית. ההגדרה נשמרת ב־Git common-dir וחלה על כל ה־worktrees המקושרים של אותו ריפו.

```bash
git config --local heavy-run.remote build-runner
heavy-run status
heavy-run -- git diff --cached --stat
```

היעד נבחר לפי סדר הקדימות הבא. ערך ריק בשכבה הראשונה שמוגדרת מבטל את הניתוב.

1. משתנה הסביבה `HEAVY_RUN_REMOTE`.
2. הערך `heavy-run.remote` בתצורת Git המקומית של הריפו.
3. שורה אחת בקובץ `${XDG_CONFIG_HOME:-$HOME/.config}/heavy-run/remote`. קובץ זה נותן ברירת מחדל גם לריפואים בלי הגדרה מקומית.

כדי להגביל ניתוב אוטומטי לריפואים מאושרים, השאירו את משתנה הסביבה ואת קובץ ברירת המחדל ללא הגדרה, והגדירו את היעד רק בתצורת Git של הריפואים שאושרו. להסרת ההגדרה מריפו השתמשו ב־`git config --local --unset heavy-run.remote`.

עם יעד מוגדר, פקודות מתוך worktree של Git רצות מרחוק כברירת מחדל. `--remote` דורש יעד מוגדר והרצה מתוך worktree עם commit קיים. אם בדיקת החיבור ל־SSH נכשלת, הפקודה רצה פעם אחת מקומית ומדפיסה אזהרה, גם עם `--remote`. כשל הכנה או אובדן חיבור אחרי בדיקת הזמינות מסיים את הבקשה בלי הרצה מקומית נוספת. הרצה שהסתיימה ביעד מחזירה את קוד היציאה של הפקודה, כולל 255. כש־heavy-run עצמו נכשל, הוא מחזיר 125 ומדפיס אבחון. השתמשו ב־`--local` לבדיקות דפדפן עם תשתית מקומית. השוו מדידות ביצועים שרצו באותה מכונה.

### מה עובר ב־SSH

- כותרת עם argv, הנתיב היחסי בתוך ה־worktree ומזהים שמחושבים מנתיבי Git. הלקוח מעביר את יתרת stdin לפקודה ומציג stdout ו־stderr תוך כדי ריצה. SSH פועל ללא PTY וללא agent forwarding.
- Git bundle של ה־HEAD ושל האובייקטים הנגישים מההיסטוריה שלו כאשר הקומיט חסר במטמון היעד. קובץ היסטורי נשאר נגיש ב־runner דרך Git גם אם הוסר או הוסף ל־`.gitignore` בקומיט מאוחר יותר. ה־index מועבר כרשומת נתיבים, מצבי קובץ ומזהי אובייקטים, עם pack של ה־blobs החדשים. כך פקודות כמו `git diff --cached --binary` רואות את ה־staging המקומי, גם כשלקובץ יש שינוי נוסף ב־worktree.
- קובצי עבודה שה־index עוקב אחריהם וקבצים חדשים שכללי ה־ignore מאפשרים. קובצי `.env`, ‏`.env.*` למעט תבניות `.env.example`, ‏`.env.sample` ו־`.env.template`, וכן שמות מקומיים נפוצים של קובצי התחברות כמו `.npmrc` ו־`.ssh`, מוחרגים. אם קובץ בנתיב מוחרג נמצא ב־HEAD או ב־index, ההרצה נפסקת לפני שליחת הקוד. קובצי התצורה של Git, כולל כתובת ה־origin וההגדרה `heavy-run.remote`, נשארים מקומיים. השתמשו ב־`.gitignore` לכל סוד מקומי בעל שם אחר.

אישור להעברה של ריפו כולל את ההיסטוריה הנגישה מה־HEAD ואת השינויים שיועלו מה־worktree. בדיקת הנתיבים חלה על ה־HEAD הנוכחי, ה־index וקובצי העבודה. השתמשו ב־`--local` כאשר ההיסטוריה או השינויים כוללים מידע המוגבל למכונה המקומית. הסרת ההגדרה עוצרת ניתוב לפי אותה הגדרה. עותקים שכבר הועברו נשארים במצב המקומי של ה־runner.

ה־runner שומר מראת Git לכל ריפו ו־checkout לכל worktree מקומי. `HEAVY_RUN_REMOTE_STATE` קובע את תיקיית המצב שלו. ברירת המחדל היא `${XDG_CACHE_HOME:-$HOME/.cache}/heavy-run/runner`. ריצות לאותו checkout נכנסות בזו אחר זו עם נעילה שנשמרת מההכנה עד סיום הפקודה. התור ותקרות הזיכרון חלים על ההכנה, `bun install` והפקודה. `--no-queue` משאיר את נעילת ה־checkout פעילה.

בכל בקשה ה־runner מנקה תוצרי הרצות קודמות. כשה־checkout קר, ה־lockfile, ‏`package.json`, ‏`bunfig.toml` או גרסת Bun השתנו, ה־runner מריץ `bun install --frozen-lockfile` בכל תיקייה עם lockfile של Bun. בין הרצות עם אותם קלטים, ה־runner שומר את `node_modules`. מטמון ההורדות של Bun נשאר בחשבון ה־runner. השתמשו ב־`--local` ל־Git submodules, לקישורים סימבוליים שיוצאים מה־worktree ולקבצים מיוחדים.

## טסטים

```bash
./test_heavy_run.sh
python3 test_remote.py -v
```

הטסטים בודקים קוד יציאה, ניקוי הסביבה, סדר בתור עם מקום אחד ועם שניים, `--preview`, שחרור מקום של תהליך שמת, והריגה בחריגה מתקרת הזיכרון. הם דורשים מנהל systemd של המשתמש.

`test_remote.py` מפעיל את הלקוח ואת ה־runner בתיקיות זמניות דרך תחליף SSH מקומי. הוא בודק את ה־index וה־worktree, זרימת הקלט והפלט, פרטיות, נעילות מקבילות, מטמון Bun, ‏status ו־fallback. הוא דורש Bash, ‏Git ו־Python ומשתמש גם בתחליף מקומי ל־Bun.

## מגבלות

- ללא מנהל systemd של המשתמש, הפקודה רצה בלי תקרת זיכרון, עם אזהרה.
- התור משותף רק למי שמשתמש באותו `HEAVY_RUN_DIR`, כלומר לאותו משתמש באותה מכונה.
