# heavy-run

עטיפה לפקודות כבדות שסוכנים מריצים במקביל על אותה מכונה: סוויטת טסטים מלאה, build, מדידה, בדיקת דפדפן.

היא עושה שלושה דברים:

1. **תור.** כל מכונה מקבלת מספר קבוע של מקומות (ברירת מחדל: מחצית מהליבות, לפחות 1). פקודה שלא קיבלה מקום ממתינה, ומדפיסה מה רץ עכשיו ומי הריץ: `waiting in queue (40s) — running now: [vitest · pid 1234 · /path · since 10:02:11]`. המקום משתחרר לבד כשהתהליך מת (`flock`).
2. **תקרת זיכרון.** הפקודה רצה ב-`systemd-run --user --scope` עם `MemoryMax` ו-`MemorySwapMax`. פקודה שחורגת נהרגת לבדה, עם קוד 137 והודעה שמזכירה את התקרה, והסוכנים והשרתים ממשיכים לרוץ.
3. **סביבה נקייה.** מסירה את `DC_DEPLOYMENT`, ‏`DC_DEPLOYMENT_DIR`, ‏`PORT`, ‏`FE_STATIC_DIR` ו-`NODE_ENV`. סוכן שרץ תחת שרת drive-coding יורש אותם, ושרת preview שעולה איתם מתנהג כמו השרת הראשי ומשתלט על הסוכנים שלו.

## שימוש

```bash
heavy-run -- bun run test                       # בתור, עם תקרה, סביבה נקייה
heavy-run --label fe-suite -- bunx vitest run   # שם שיופיע בתור
heavy-run --preview --label fso2 -- env DC_DEPLOYMENT=fso2 PORT=4397 bun src/bin/drive-coding.ts
heavy-run status                                # מי מחזיק מקום ומי ממתין
```

- `--local` — בוחר במפורש את התור של המכונה המקומית.
- `--preview` / `--no-queue` — בלי מקום בתור. לשרת שרץ לאורך זמן: הוא מקבל תקרה וסביבה נקייה, אבל לא חוסם טסטים. את משתני הפריסה שלו מגדירים במפורש אחרי `env`, כמו בדוגמה.
- `--keep-env` — לא להסיר את משתני הפריסה.
- `--mem-max SIZE` (ברירת מחדל `2G`), ‏`--swap-max SIZE` (ברירת מחדל `512M`).
- `--mem-high SIZE` — תקרה רכה שמאטה במקום להרוג. כבויה בברירת מחדל: תקרה רכה נמוכה עלולה להקפיא פקודה לדקות ארוכות במקום להפיל אותה.

משתני סביבה: `HEAVY_RUN_SLOTS`, ‏`HEAVY_RUN_MEM_MAX`, ‏`HEAVY_RUN_SWAP_MAX`, ‏`HEAVY_RUN_MEM_HIGH`, ‏`HEAVY_RUN_DIR` (ברירת מחדל `$XDG_RUNTIME_DIR/heavy-run`).

קוד היציאה הוא של הפקודה; 124 אם ההמתנה בתור נקטעה.

## מה נחשב כבד

סוויטה מלאה (`vitest run` בלי סינון, `bun test` על חבילה), build של production, מדידות ביצועים, בדיקות דפדפן. טסט ממוקד בקובץ אחד לא צריך תור.

להרצת סוויטה או build ב־runner, ראו [remote-test](../remote-test/README.md).

## התקנה

```bash
ln -sf "$PWD/heavy-run" ~/.local/bin/heavy-run
```

## טסטים

```bash
./test_heavy_run.sh
```

הטסטים בודקים קוד יציאה, ניקוי הסביבה, סדר בתור עם מקום אחד ועם שניים, `--preview`, שחרור מקום של תהליך שמת, והריגה בחריגה מתקרת הזיכרון. הם דורשים מנהל systemd של המשתמש.

## מגבלות

- ללא מנהל systemd של המשתמש, הפקודה רצה בלי תקרת זיכרון, עם אזהרה.
- התור משותף רק למי שמשתמש באותו `HEAVY_RUN_DIR`, כלומר לאותו משתמש באותה מכונה.
