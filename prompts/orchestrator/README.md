# מתזמר ביצוע

פרומפט לסוכן שמבצע בריף מאושר באמצעות סוכנים מבצעים, כדי שהסוכן שמדבר עם המשתמש
לא יצטרך לעקוב אחרי הביצוע.

## למה

מעקב אחרי סוכנים מבצעים הוא רוב הטוקנים בעבודה מרובת סוכנים: כל הודעת התקדמות וכל
בדיקת מצב נכנסות להקשר של מי שעוקב. החלוקה כאן מעבירה את המעקב לסוכן זול יותר,
ומשאירה לסוכן התכנון רק שיחה, תכנון והכרעות.

## התפקידים

| תפקיד | מה עושה | מה לא עושה |
|---|---|---|
| **סוכן התכנון** | מדבר עם המשתמש, כותב בריף, מפעיל את המתזמר, מקבל ממנו הסלמות | לא עוקב אחרי הביצוע ולא בודק מצב מיוזמתו |
| **מתזמר** (הפרומפט כאן) | מפרק את הבריף, מחליט לכל שלב אם להעביר למבצע או לבצע בעצמו (כללים בפרומפט), עוקב, מאמת, מקמט, מעדכן קובץ סטטוס | לא מדבר עם המשתמש, לא משנה היקף |
| **מבצע** | מבצע שלב אחד בסביבת עבודה משלו ומחזיר תוצר | לא מפעיל סוכנים אחרים |

## הזרימה

1. סוכן התכנון כותב בריף מאושר לתיקיית משימה.
2. סוכן התכנון מפעיל את המתזמר כסוכן־ילד שלו, שולח לו הודעת הפעלה (ר' למטה) ולא
   ממתין ולא עוקב.
3. המתזמר מבצע, ומעדכן `status.md` בתיקיית המשימה אחרי כל שינוי מצב.
4. **הסלמה:** רק כשהמתזמר נתקע, אחרי שחיפש פתרון מתועד, או כשהגיע לשער שדורש
   אישור משתמש. ההסלמה נשלחת להורה (סוכן התכנון), שמעדכן את המשתמש ובודק מה אפשר
   לעשות. התשובה חוזרת למתזמר כהודעה.
5. המשתמש שואל את סוכן התכנון "מה המצב?" ⇒ סוכן התכנון קורא את `status.md`, ולא את
   הסשנים.

אין התראות שוטפות ואין הודעת סיום אוטומטית להורה. מצב שוטף נמצא בקובץ הסטטוס.

## הפעלה

הודעת ההפעלה למתזמר מכילה שלושה נתיבים:

```
בצע לפי <נתיב ל-prompt.md>.
קובץ התאמות: <נתיב לקובץ ההתאמות של המופע>.
בריף: <נתיב לבריף>.
```

## קובץ ההתאמות

קובץ פרטי של המופע, שהפרומפט מתייחס אליו בשמות תפקידים. עליו להגדיר:

| מפתח | משמעות |
|---|---|
| `מבצעים` | אילו סוכנים זמינים כמבצעים, ולאיזה סוג עבודה כל אחד |
| `כלי סשנים` | שמות הכלים לפתיחה, שליחה, בדיקת מצב וסגירה של סוכן, ולהודעה להורה |
| `חיפוש תיעוד` | איך מחפשים אם בעיה כבר נפתרה (כלי, מקורות) |
| `כללים` | איפה כללי המופע: קומיט ודחיפה, תהליכים, סביבות עבודה, אישורים |
| `תיקיית משימות` | איפה נמצאים בריפים וקובצי סטטוס |

## קבצים

- `prompt.md` — הפרומפט עצמו.
